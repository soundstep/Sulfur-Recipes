  <action>
Create `artifacts/api-server/Dockerfile` as a multi-stage build.

**Build context:** docker-compose will set context to repo root so all workspace packages are available.

**Stage 1 — deps (install all workspace deps):**
```dockerfile
FROM node:24-alpine AS deps
RUN corepack enable && corepack prepare pnpm@latest --activate
WORKDIR /app
# Copy workspace manifests first (layer cache)
COPY package.json pnpm-workspace.yaml pnpm-lock.yaml ./
COPY lib/api-zod/package.json ./lib/api-zod/
COPY lib/api-spec/package.json ./lib/api-spec/
COPY lib/api-client-react/package.json ./lib/api-client-react/
COPY artifacts/api-server/package.json ./artifacts/api-server/
# Install all deps (including devDeps needed for build)
RUN pnpm install --frozen-lockfile
```

**Stage 2 — builder (run esbuild):**
```dockerfile
FROM deps AS builder
# Copy source after install for better cache
COPY lib/ ./lib/
COPY artifacts/api-server/ ./artifacts/api-server/
WORKDIR /app/artifacts/api-server
RUN pnpm run build
```
The build output is `artifacts/api-server/dist/index.mjs` (and pino transport files).

**Stage 3 — runner (minimal image, prod deps only):**
```dockerfile
FROM node:24-alpine AS runner
RUN corepack enable && corepack prepare pnpm@latest --activate
WORKDIR /app
# Only copy what's needed to run
COPY --from=builder /app/artifacts/api-server/dist ./dist
# pino needs thread-stream/worker_threads — copy node_modules that contain native modules
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
ENV NODE_ENV=production
CMD ["node", "--enable-source-maps", "./dist/index.mjs"]
```

PORT env var must be supplied at runtime via docker-compose — do NOT hardcode it or set a default in the Dockerfile (the app throws if PORT is absent, which is the correct behavior to ensure docker-compose always provides it).
  </action>

  <name>Task 2: Dockerfile for sulfur-recipe-finder (multi-stage, nginx serve)</name>

Create `artifacts/sulfur-recipe-finder/Dockerfile` as a multi-stage build that produces a static nginx image.

**Key constraint:** The Vite config has `@assets` alias pointing to `../../attached_assets` relative to the package root — meaning `/app/attached_assets` in the build context. The build context must be the repo root.

**Stage 1 — builder (vite build):**
```dockerfile
FROM node:24-alpine AS builder
RUN corepack enable && corepack prepare pnpm@latest --activate
WORKDIR /app
# Workspace manifests for layer cache
COPY package.json pnpm-workspace.yaml pnpm-lock.yaml ./
COPY lib/api-zod/package.json ./lib/api-zod/
COPY lib/api-spec/package.json ./lib/api-spec/
COPY lib/api-client-react/package.json ./lib/api-client-react/
COPY artifacts/sulfur-recipe-finder/package.json ./artifacts/sulfur-recipe-finder/
RUN pnpm install --frozen-lockfile
# Source and assets
COPY lib/ ./lib/
COPY attached_assets/ ./attached_assets/
COPY artifacts/sulfur-recipe-finder/ ./artifacts/sulfur-recipe-finder/
WORKDIR /app/artifacts/sulfur-recipe-finder
RUN pnpm run build
```
Output: `artifacts/sulfur-recipe-finder/dist/public/` (index.html + assets)

**Stage 2 — runner (nginx:alpine, no Node needed):**
```dockerfile
FROM nginx:alpine AS runner
COPY --from=builder /app/artifacts/sulfur-recipe-finder/dist/public /usr/share/nginx/html
# nginx default config serves on port 80; frontend proxies /api to backend via docker-compose
EXPOSE 80
```

Do NOT use `vite preview` in the final image — nginx is lighter and production-appropriate. The `/api` proxy to the backend will be configured in docker-compose via nginx conf (handled in plan 02), or alternatively with a simple nginx.conf override if needed.

If the frontend makes direct `/api` requests that need to be proxied: add an `nginx.conf` override in the same Dockerfile stage that proxies `/api` to `http://api:3000`. Check `artifacts/sulfur-recipe-finder/src/` for how the API base URL is configured before deciding.
  </action>
