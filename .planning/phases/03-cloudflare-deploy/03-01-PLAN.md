# Plan 03-01: Extract recipe logic into `lib/recipe-core`

## Goal

Move all platform-agnostic recipe logic out of `artifacts/api-server/src/routes/recipes.ts` into a new workspace package `lib/recipe-core`. Define a `CacheStore` interface. Wire Express server to use the new package with an in-memory adapter.

## Why first

The Worker (03-02) and the Express server both need the same core logic. Creating this shared package first avoids duplication and ensures the portability constraint is met at the source.

### 4. Create in-memory `CacheStore` adapter (`lib/recipe-core/src/adapters/memory.ts`)

```typescript
export class MemoryCacheStore implements CacheStore {
  private store = new Map<string, { value: string; expiresAt: number }>();

  async get(key: string): Promise<string | null> {
    const entry = this.store.get(key);
    if (!entry || Date.now() > entry.expiresAt) return null;
    return entry.value;
  }

  async put(key: string, value: string, ttlSeconds: number): Promise<void> {
    this.store.set(key, { value, expiresAt: Date.now() + ttlSeconds * 1000 });
  }
}
```

### 5. Update `artifacts/api-server`

- Add `@workspace/recipe-core` to `dependencies` in `package.json`
- Rewrite `routes/recipes.ts`:
  - Remove all extracted logic
  - Import `getRecipesData`, `MemoryCacheStore` from `@workspace/recipe-core`
  - Create a module-level `const cache = new MemoryCacheStore()` (same behavior as before)
  - Route handlers call `getRecipesData(cache)` — refresh route calls `cache.invalidate()` (add `invalidate()` to `MemoryCacheStore`)
- Run `pnpm typecheck` in `artifacts/api-server` to confirm no regressions
