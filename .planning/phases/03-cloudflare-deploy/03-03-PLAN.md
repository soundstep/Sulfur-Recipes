# Plan 03-03: Cloudflare Pages deploy + Pages Functions API proxy

## Goal

Deploy the React frontend to Cloudflare Pages. Use a Pages Function (`functions/api/[...path].ts`) to proxy `/api/*` requests to the Worker, keeping the frontend on the same origin and requiring zero `VITE_API_URL` configuration.

## Depends on

03-02 — Worker must be deployed and its URL known.

## Tasks

### 1. Create Pages Functions proxy (`artifacts/sulfur-recipe-finder/functions/api/[...path].ts`)

```typescript
interface Env {
  WORKER_URL: string; // Pages env var pointing at the Worker
}

export const onRequest: PagesFunction<Env> = async (context) => {
  const { request, env, params } = context;
  const path = (params["path"] as string[]).join("/");
  const workerUrl = `${env.WORKER_URL}/api/${path}`;

  const url = new URL(request.url);
  const targetUrl = `${workerUrl}${url.search}`;

  // Forward the request to the Worker
  const workerResponse = await fetch(targetUrl, {
    method: request.method,
    headers: request.headers,
    body: request.method !== "GET" && request.method !== "HEAD"
      ? request.body
      : undefined,
  });

  return workerResponse;
};
```

This means the frontend calls `/api/recipes` as it always has. The Pages Function transparently forwards to the Worker. No CORS needed.

### 2. Set `WORKER_URL` environment variable in Pages project

After deploying the Worker (03-02), set:
```
WORKER_URL=https://sulfur-recipes-api.<account>.workers.dev
```

Via Cloudflare Dashboard → Pages → Settings → Environment Variables, or via wrangler:
```bash
# Not available via wrangler CLI for Pages env vars — use dashboard or API
```

### 3. Build and deploy frontend to Pages

First, ensure Vite build works:
```bash
cd artifacts/sulfur-recipe-finder && pnpm build
```

Create the Pages project (first time only):
```bash
wrangler pages project create sulfur-recipes --production-branch main
```

Deploy:
```bash
cd artifacts/sulfur-recipe-finder && wrangler pages deploy ./dist --project-name sulfur-recipes
```

### 4. Wire a root-level deploy script

Add to root `package.json`:
```json
{
  "scripts": {
    "deploy": "pnpm --filter @workspace/sulfur-recipe-finder build && wrangler deploy --config artifacts/worker/wrangler.jsonc && wrangler pages deploy artifacts/sulfur-recipe-finder/dist --project-name sulfur-recipes"
  }
}
```

This gives a single `pnpm deploy` command that ships both services.

### 5. Verify end-to-end

- Open the Pages URL in browser
- App loads, searches return recipe data
- Network tab: `/api/recipes` returns 200 via Pages Function proxy

### 6. Update ROADMAP.md and STATE.md

Mark Phase 3 complete in ROADMAP.md progress table. Update STATE.md with deployed URLs.

## Pages Functions notes

- `functions/` directory at the Vite project root is picked up automatically by Pages
- `[...path].ts` is a catch-all route matching `/api/anything`
- `WORKER_URL` must be set in Pages env vars (not in `.env` — that's for local Vite dev only)
- For local testing of the proxy: `wrangler pages dev ./dist --binding WORKER_URL=http://localhost:8787`

## Portability Note

The Pages Function proxy is the only CF-Pages-specific artifact. If moving to Vercel, replace with a Vercel Edge Function or Next.js API route that does the same proxy. The Worker URL just changes to the new API host. Frontend code is unchanged.
