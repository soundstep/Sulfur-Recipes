## 2. Platform Deep-Dives

### Render — Recommended ⭐
**Free tier status (2026):** Active. Hobby workspace = $0/month, up to 25 services.

- **Express API:** Free Web Service (Node runtime or Docker). 512 MB RAM, 0.1 vCPU.
- **Static frontend:** Free Static Site (CDN-hosted, instant cache invalidation).
- **Sleep behavior:** Spins down after **15 minutes** of no inbound HTTP/WS traffic. Takes **~60 seconds** to wake. During spin-down, in-memory cache is lost.
- **Usage cap:** **750 free instance-hours/month** (~31 days at continuous run = 744 hours, so barely fits one service running 24/7). With spin-down behavior, hours are only consumed when running, so sleep helps extend free quota. Two free web services running 24/7 would exceed the 750h cap mid-month.
- **Monorepo:** Explicit support via `rootDir` per service and build filters in `render.yaml`. Each monorepo package deploys as a separate service.
- **pnpm:** Supported via `npm install -g pnpm && pnpm install` in build command, or use Docker.
- **Docker:** Supported on free tier.
- **Scraping concern:** Render flags "uncommonly high volume of service-initiated outbound traffic" and may suspend free services. Light scraping with 1h TTL cache should be fine.

---

### Railway — Viable (with caveats)
**Free tier status (2026):** Downgraded. The permanent "Free" plan gives only **$1/month** in compute credits — enough for ~1.5 days of a minimal container. Practically, you need the **Hobby plan at $5/month** which includes $5 of usage credits.

- **Express API:** Persistent container, **no sleep/spin-down** on Hobby. Survives restarts with in-memory cache intact between requests (only lost on redeploy/restart).
- **Static frontend:** Can serve as a static deployment from the same or separate service; or use Vercel/Netlify for the frontend only.
- **Monorepo:** First-class support. Configure root directory per service.
- **pnpm:** Works natively (declare in `package.json` `packageManager` field or install manually).
- **Docker:** Supported.
- **Verdict for free use:** Trial ($5 one-time for 30 days) gives enough time to test. After that, pure free ($1/mo) is not viable. At $5/mo Hobby it becomes very competitive.

---

### Fly.io — No True Free Tier (2026)
**Free tier status (2026):** **Discontinued for new accounts** as of October 7, 2024. Fly.io is now strictly **Pay As You Go** (credit card required). Legacy users who had the free Hobby plan before that date retain their free allowances.

- Cheapest config: `shared-cpu-1x` 256 MB = **$2.02/month** (iad region). A minimal Express app could fit here.
- Auto-stop/auto-start is supported (Machines stop when idle, you're only billed for started time).
- **For new users in 2026: not a free option.** Excluded from free recommendations.

---

### Vercel — Frontend Only (Free)
**Free tier status (2026):** Active. Hobby plan = $0, forever.

- **Express API:** ❌ Not supported as a persistent process. Vercel only runs **serverless functions** (stateless, billed per invocation). Express can be adapted via `@vercel/node` but each function invocation is a fresh process — **in-memory cache is lost between requests**.
- **Static frontend:** ✅ Excellent — global CDN, instant deploys, custom domains.
- **Monorepo:** Native support (Vercel has first-class monorepo config).
- **Use case:** Deploy the React/Vite frontend here for free. Use a separate platform for the Express API.
- **Hobby limit:** 1M function invocations/month, 100 GB bandwidth, 4 CPU-hours active compute/month.

---

### Netlify — Frontend Only (Free)
**Free tier status (2026):** Active. Free plan = $0, 300 credits/month.

- **Express API:** ❌ Serverless Functions only (same problem as Vercel — stateless, no persistent cache).
- **Static frontend:** ✅ Excellent — global CDN, Git-driven CI/CD.
- **Credits model:** 300 credits/month free. Production deploys cost 15 credits each (= 20 free deploys/month). Bandwidth = 20 credits/GB. Compute = 10 credits/GB-hr.
- **Use case:** Same as Vercel — frontend only. API must go elsewhere.

---

### Hugging Face Spaces — Unconventional But Works
**Free tier status (2026):** Active. CPU Basic hardware = 2 vCPU / 16 GB RAM, **free**.

- **Express API:** ✅ Via **Docker Space**. You can run a full Node.js Express server in a Docker container. The 16 GB RAM is extremely generous.
- **Static frontend:** ✅ Can be served from same Docker container (Express serves static files), or via a separate Static HTML Space.
- **Sleep behavior:** Free Spaces **sleep after inactivity**. Exact threshold not documented but community reports ~30 min–1 hour. In-memory cache lost on sleep.
- **Port restriction:** Only ports **80, 443, and 8080** are accessible externally. Your Express app must listen on 7860 (default) or 8080.
- **Monorepo / pnpm:** You build the Dockerfile yourself, so full control. pnpm works fine in Dockerfile.
- **Scraping concern:** Outbound HTTP (to `sulfur.wiki.gg`) is allowed on ports 80/443. However, Hugging Face ToS is ML-focused; aggressive scraping might raise flags. Light use with caching should be fine.
- **Gotcha:** This is a ML demo platform — community perception and ToS enforcement may differ from a traditional cloud host. Not designed for production Node apps but technically works.

---

### Oracle Cloud Free Tier — Most Powerful Free Option
**Free tier status (2026):** Active and **truly unlimited** (Always Free, no expiry).

- **Express API:** ✅ Full Linux VMs. Ampere A1 ARM: **up to 4 OCPUs + 24 GB RAM** shared across up to 4 instances (Always Free). You have root access to run Node 24, pnpm, Docker, anything.
- **Static frontend:** ✅ Serve via Nginx/Caddy on the VM, or use Oracle's Object Storage (free tier) with a CDN rule.
- **Sleep behavior:** ❌ **No sleep** — always-on VMs.
- **In-memory cache:** Survives indefinitely (until you redeploy or the VM restarts).
- **Monorepo / pnpm / Node 24:** Full control — install whatever you want.
- **Docker:** ✅ Full Docker support.
- **Downsides:**
  - Requires significant manual DevOps setup (Nginx, systemd, SSL via Certbot, etc.)
  - Credit card required to sign up (not charged unless you upgrade)
  - Account may be **reclaimed if deemed idle for 30+ days** (Oracle ToS) — keep services running
  - Capacity availability is inconsistent; popular regions (us-ashburn-1) often show "out of capacity" for Always Free ARM instances
  - Not beginner-friendly

## 4. Top 3 Recommendations

### 🥇 #1 — Render (Frontend + API, fully free)

**Why:** Render is the best balance of zero-cost, zero-friction, and actual support for persistent Node.js services in 2026.

| Aspect | Detail |
|---|---|
| Frontend | Deploy as a **Render Static Site** — free, CDN-backed, auto-deploys from Git |
| API | Deploy as a **Render Free Web Service** — Node 24 runtime, 512 MB RAM |
| pnpm monorepo | Use `render.yaml` with `rootDir: packages/api` and `rootDir: packages/web` for independent deployments |
| Sleep | API sleeps after 15 min idle; cache lost on wake-up (acceptable per requirements) |
| Free hours cap | 750 h/month shared; if only the API sleeps when unused, you stay well within limits |
| Risk | Render may suspend services if they generate excessive outbound traffic; 1h cache TTL means at most ~24 scrape calls/day — well below any threshold |

**Setup summary:**
```yaml
# render.yaml
services:
  - type: web
    name: sulfur-api
    runtime: node
    rootDir: packages/api
    buildCommand: npm install -g pnpm && pnpm install --frozen-lockfile
    startCommand: node dist/index.js
    plan: free
    envVars:
      - key: NODE_ENV
        value: production

  - type: web
    name: sulfur-frontend
    runtime: static
    rootDir: packages/web
    buildCommand: npm install -g pnpm && pnpm install --frozen-lockfile && pnpm build
    staticPublishPath: dist
    plan: free
```

---

### 🥈 #2 — Vercel (Frontend, free) + Render Free (API)

**Why:** If you want the absolute best static hosting DX, Vercel's CDN and deploy previews are best-in-class. Pair it with Render's free API tier.

| Aspect | Detail |
|---|---|
| Frontend | Vercel Hobby — global CDN, Git previews, instant rollback, free forever |
| API | Render Free Web Service (same as option #1) |
| pnpm monorepo | Vercel has native monorepo support (set root directory to `packages/web`); Render handles `packages/api` |
| Frontend env | Set `VITE_API_URL=https://your-render-service.onrender.com` in Vercel env vars |
| Tradeoff | Two platforms to manage; CORS config needed on Express API to allow Vercel domain |

---

### 🥉 #3 — Oracle Cloud Always Free (Frontend + API, self-managed)

**Why:** Best for maximum control, zero cold starts, persistent in-memory cache, and unlimited resources — at the cost of DevOps effort.

| Aspect | Detail |
|---|---|
| VM | 1× Ampere A1 (2 vCPU / 12 GB RAM — well within Always Free quota) |
| Frontend | Nginx serves Vite `dist/` as static files; or separate Object Storage bucket |
| API | Express.js on Node 24, managed by PM2 or systemd, always running |
| pnpm monorepo | Clone repo, install pnpm, `pnpm install`, build all packages |
| Sleep | None — persistent process, cache survives indefinitely |
| SSL | Certbot + Let's Encrypt (free) |
| Difficulty | High — you manage the VM, OS, SSL, process manager, deployments |
| Risk | Oracle may reclaim idle instances; capacity in popular regions is limited |

## 5. Recommended Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    USER'S BROWSER                           │
└────────────────────┬────────────────────────────────────────┘
                     │
          ┌──────────▼──────────┐
          │   Static Hosting    │   ← Render Static Site (free)
          │   React + Vite      │     OR Vercel Hobby (free)
          │   packages/web      │     Global CDN, HTTPS, custom domain
          └──────────┬──────────┘
                     │ API calls to /api/*
                     │ (CORS: allow static site origin)
          ┌──────────▼──────────┐
          │   Express API       │   ← Render Free Web Service
          │   Node 24           │     packages/api
          │   In-memory cache   │     512 MB RAM, 0.1 vCPU
          │   (1h TTL)          │     Sleeps after 15min idle
          └──────────┬──────────┘
                     │ HTTP scrape (max ~24×/day with 1h cache)
          ┌──────────▼──────────┐
          │  sulfur.wiki.gg     │   ← External wiki (scraped)
          └─────────────────────┘
```

### CORS configuration (Express)
```js
// packages/api/src/index.ts
import cors from 'cors';

app.use(cors({
  origin: [
    'https://your-app.onrender.com',   // Render static
    'https://your-app.vercel.app',      // Vercel (if used)
    'http://localhost:5173',            // Local dev
  ]
}));
```

### pnpm monorepo build strategy for Render
```yaml
# render.yaml (at repo root)
services:
  - type: web
    name: sulfur-api
    runtime: node
    rootDir: packages/api
    buildCommand: |
      npm install -g pnpm@latest
      pnpm install --frozen-lockfile --filter @sulfur/api...
      pnpm --filter @sulfur/api build
    startCommand: node dist/index.js
    plan: free

  - type: web
    name: sulfur-frontend
    runtime: static
    rootDir: packages/web
    buildCommand: |
      npm install -g pnpm@latest
      pnpm install --frozen-lockfile --filter @sulfur/web...
      pnpm --filter @sulfur/web build
    staticPublishPath: dist
    plan: free
    headers:
      - path: /*
        name: Cache-Control
        value: no-cache
```

## 6. Pitfalls Specific to This App

### In-memory Cache + Container Sleep
The Express server caches scraped data in memory with a 1h TTL. Any platform that spins down the container (Render free, HF Spaces free) will lose this cache on wake-up. **This is acceptable** per your requirements — the first request after wakeup will trigger a fresh scrape. The ~60s cold start on Render is the bigger UX concern; consider adding a "loading" state in the frontend when the API is slow to respond.

**Mitigation options:**
- Add a `GET /health` ping endpoint; use UptimeRobot (free) to ping it every 14 minutes to prevent Render sleep. Note: Render's ToS does not explicitly forbid this, but it does consume your 750 free instance-hours faster.
- If cache warmth matters, Oracle Cloud Always Free eliminates this problem entirely.

### Wiki Scraping Rate Limits
`sulfur.wiki.gg` is Fandom/wiki.gg hosted. With a 1h TTL and presumably a modest number of endpoints, you'd be making ~24 requests/day per cached resource. This is well within any reasonable rate limit. However:
- Set a proper `User-Agent` header identifying your app (e.g., `sulfur-recipes/1.0`)
- Do not parallelize scrape calls aggressively
- Consider caching responses to disk on Oracle Cloud (avoids cold-start scrape latency)

### pnpm + Render Build Environment
Render's default Node environment uses npm. You must explicitly install pnpm in your build command:
```bash
npm install -g pnpm@latest && pnpm install --frozen-lockfile
```
Alternatively, use a `Dockerfile` (supported on free tier) to pin exact pnpm and Node 24 versions:
```dockerfile
FROM node:24-slim
RUN npm install -g pnpm@latest
WORKDIR /app
COPY pnpm-lock.yaml pnpm-workspace.yaml package.json ./
COPY packages/api/package.json ./packages/api/
RUN pnpm install --frozen-lockfile --filter @sulfur/api...
COPY packages/api ./packages/api
RUN pnpm --filter @sulfur/api build
CMD ["node", "packages/api/dist/index.js"]
```

### Node 24 Availability
- **Render:** Node versions are configurable via `NODE_VERSION` env var. Node 24 is available.
- **Vercel:** Supports Node 22 as of early 2026; Node 24 support may require checking current docs.
- **Railway:** Any version via Docker or `.node-version` file.
- **Oracle Cloud:** Install directly with `nvm` — any version available.
- **HF Spaces:** Full control via Dockerfile.

### Render's 750 Free Instance-Hours/Month
If you run **both** the frontend (static — no hours consumed) and the API (web service — hours consumed when awake), and the API sleeps regularly, you should comfortably stay within 750h/month. 750 hours = 31.25 days, so a single service could theoretically run 24/7. With sleep, a moderately-used API will stay well under the limit.

### Render Free Service-Initiated Traffic Policy
Render may suspend free services that generate "uncommonly high outbound traffic." Scraping a wiki with 1h caching = minimal external calls. This should never trigger suspension. If you add more scraped endpoints in the future, keep the TTL generous.

### Vercel Hobby — Commercial Use Restriction
Vercel's Hobby plan ToS restricts it to **personal, non-commercial use**. If Sulfur-Recipes is ever monetized, upgrade to Pro ($20/mo) or switch frontend hosting.
